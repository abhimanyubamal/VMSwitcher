VM Switcher Operator Guide

One page. Read it once and you can run the system.

What it does. Two virtual machines run the VirtuoSIS IICC service. The Primary normally serves everyone. The Secondary is the spare and is normally OFF. If the Primary stops or freezes, or its whole server goes down, VM Switcher wakes the Secondary within about 10 seconds. You do not need to do anything for that to happen.
Two servers, same app. The Primary runs on server 10.10.140.160 and the Secondary on server 10.10.140.140. VM Switcher is installed on both and they keep each other informed, so you can use either server: you see both VMs and every button works on both. The top line says which server you are on. The pill Other server: connected must be green.

1. Read the lights

Green: OK
Running and answering.
Yellow: SUSPENDED
Sleeping (hibernated). Wakes in seconds.
Grey: ERROR
Broken, frozen, or missing.
Dark: OFF
Switched off.
Blinking
Busy starting or saving. Wait.

Normal day: Primary green, Secondary dark (OFF), ready to take over. The coloured dot in the taskbar corner shows the same at a glance: green is fine, amber means look, red means act now.

2. Read the banner

The wide bar at the top always says, in one sentence, what is going on. If it is green you are done. If it is amber or red, it tells you which button to press.

3. The buttons

ButtonWhen to use it
1Turn ON PrimaryAfter a failover, once the Primary problem is fixed. If the Primary is frozen, this button turns orange and says Restart Primary.
2Turn ON SecondaryOnly while the Primary is OFF (both VMs use the same IP address). Normally the watchdog does this for you.
3Turn OFF SecondaryShut the spare down cleanly (nothing is lost). It only works while the Primary is green, so nobody loses service.
4Planned stop of PrimaryBefore patching or restarting the Primary. Choose Yes to move users to the Secondary first. No alarm is raised.
5Pause / resume auto-failoverMaintenance mode: the watchdog only watches. Always resume it afterwards.
6What happenedThe history in plain English, newest first.
7VM hand-off historyEvery time one VM stopped and the other took over, and how long it took.
8Failover test (dry run)Shows what would happen if the Primary failed right now. Changes nothing. Safe to press any time.
9Open VM consoleSee the screen of either VM.

A greyed-out button tells you, in yellow text, why it cannot be used right now. You can also press the number keys 1-9.

4. When something goes wrong

"Primary is DOWN ... Secondary is serving."
Users are fine. Fix or restart the Primary, then press 1. Two minutes after the Primary is starting again, VM Switcher holds it paused for a moment (its light is yellow), shuts the Secondary down cleanly, then lets the Primary continue. Both VMs use the same IP address, so they never run together, and no data is lost.
"NOBODY IS SERVING."
Press 1. If the Primary will not start, press 2. Then call IT.
"The watchdog service is not running."
There is no automatic protection. Restart the server, or open services.msc and start VM Switcher Watchdog.

5. Practise (fire drill)

Install VM Switcher in Demo / training mode on any PC. A purple panel appears with buttons such as Crash the Primary. Press one and watch the lights, the banner, and the history react, exactly as they would for real. Nothing real is touched.

6. Good to know

  • Every button press is recorded with the Windows user name. See the Actions by people tab.
  • Closing the window keeps VM Switcher in the taskbar corner, so pop-ups still appear. Protection runs in the background either way.
  • VM Switcher never jumps in front of your work. When something happens, its taskbar button flashes and a small pop-up appears in the corner.
  • A grey card with a ? means the other server cannot be reached. If that server is really down, the Secondary is started automatically.
  • Servers often have no speakers. The red strip and the pop-up are the alarm; the sound is a bonus.
  • After a server reboot, VM Switcher waits 5 minutes for Hyper-V to start the Primary before it fails over.
  • Settings live in C:\ProgramData\VMSwitcher\config.json. Restart the VM Switcher Watchdog service after you change them.
  • Logs: C:\ProgramData\VMSwitcher\logs and the Windows Event Viewer, under Application, source VMSwitcher.
  • Terminal users: VMSwitcherTerminal.exe 3 runs option 3 directly, for scripts.
